# 功能审计流程

## 用法
- `/audit` — 全局审计（所有功能）
- `/audit F01` — 审计特定功能
- `/audit F01 F03` — 审计多个功能

## 执行步骤

### 1. 确定审计范围
- 无参数：读取 `record/project/index.md` 获取全部功能列表
- 有参数：只审计指定的 FXX 功能

### 2. 读取功能详情
读取范围内的 `features/fXX-*.md` 文件，提取：
- 当前实现状态
- 变化历史中的测试记录
- 已知问题

### 3. 检查每个功能
读取功能涉及的所有核心源文件，检查：
- **测试覆盖**：是否有测试记录？最近一次测试结果？
- **已知问题**：是否有未解决的问题？
- **代码风险**：
  - 跨文件重复代码
  - 缺少错误处理
  - 硬编码值
  - 未验证的外部依赖
  - 边界条件问题

### 4. 输出报告

```markdown
## 审计报告 — YYYY-MM-DD (UTC+8)
审计范围：全局 / F01, F03

### 🔴 高优先级 (P0-P1)
- [FXX] 问题描述 → 建议：解决方案

### 🟡 中优先级 (P2)
- [FXX] 问题描述 → 建议：解决方案

### ⚪ 待测试 (P3)
- [FXX] 功能名 — 未验证的关键路径
  - 建议测试命令：`...`
```

### 5. 更新文档
- 在对应 `features/fXX-*.md` 的「状态」节标注发现的问题
- 在「变化」节追加 `[审计]` 条目（如果发现了新问题）
- 增量更新 `index.md` 状态列

### 6. 提交
```bash
git commit -m "docs(audit): 审计 [范围] 发现 N 个问题"
```

## 优先级标准
| 级别 | 含义 |
|------|------|
| P0 | 数据丢失、服务不可用 |
| P1 | 核心功能受损 |
| P2 | 非核心问题、代码质量 |
| P3 | 改善建议 |
