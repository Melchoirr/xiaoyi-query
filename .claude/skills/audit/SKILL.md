# audit

## 用法
- `/audit` — 全局审计（所有功能）
- `/audit F01` — 审计特定功能
- `/audit F01 F03` — 审计多个功能

## 执行步骤

### 1. 确定审计范围

- 无参数：读取 `record/project/index.md` 获取全部功能列表
- 有参数：只审计指定的 FXX 功能

### 2. 读取功能详情

读取范围内的 `record/project/features/fXX-*.md` 文件，提取：
- 当前实现状态
- 变化历史中的测试记录（最近一次结果）
- 已知问题及其状态

### 3. 检查每个功能

读取功能涉及的所有核心源文件，检查：
- **测试覆盖**：是否有测试记录？最近一次测试结果是什么？
- **已知问题**：是否有未解决的问题？优先级如何？
- **代码风险**：
  - 跨文件重复代码
  - 缺少错误处理（try/except 覆盖不足）
  - 硬编码值（magic numbers、固定路径）
  - 未验证的外部依赖
  - 潜在的边界条件问题
  - 并发/竞争风险

### 4. 输出报告

按优先级排序输出审计报告：

```markdown
## 审计报告 — YYYY-MM-DD (UTC+8)
审计范围：全局 / F01, F03

### 🔴 高优先级 (P0-P1)
- [FXX] 问题描述 → 建议：解决方案

### 🟡 中优先级 (P2)
- [FXX] 问题描述 → 建议：解决方案

### ⚪ 待测试 (P3)
- [FXX] 功能名 — 未验证的关键路径
  - 建议测试命令：`...`
```

每次审计都应产出可执行的改进建议（具体的命令、代码修改方案）。

### 5. 更新文档

- 在对应 `features/fXX-*.md` 的「状态」节标注发现的问题
- 在「变化」节追加 `[审计]` 条目（如果发现了新问题）
- 增量更新 `index.md` 状态列（如状态发生变化）
- 全局问题汇总表从 features/*.md 聚合，加链接

### 6. 提交

```bash
git commit -m "docs(audit): 审计 [范围] 发现 N 个问题"
```

## 优先级标准

| 级别 | 含义 | 示例 |
|------|------|------|
| P0 | 数据丢失、服务不可用 | 写入覆盖数据、启动崩溃 |
| P1 | 核心功能受损 | 预测结果错误、训练不收敛 |
| P2 | 非核心问题、代码质量 | 除零风险、重复代码、缺少依赖声明 |
| P3 | 改善建议 | 性能优化、更好的错误信息 |
