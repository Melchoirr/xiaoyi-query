# 功能审计流程

## 执行步骤

### 1. 读取全部功能详情
读取 `record/project/index.md` 获取功能清单，然后读取 `record/project/features/` 下所有对应的 `fXX-*.md` 文件，提取：
- 测试结果状态（✅通过 / ❌失败 / ⚪未测试）
- 已知问题列表及其状态
- 实现状态
- 核心文件列表

### 2. 检查每个功能
对每个功能，读取其核心文件（可能涉及多个源文件），检查：
- **测试覆盖**：测试结果是否为 ⚪未测试？
- **已知问题**：是否有未解决的问题？优先级？
- **代码风险**：
  - 是否有跨文件的重复代码
  - 是否缺少错误处理（try/except 覆盖不足）
  - 是否有硬编码值（magic numbers、固定路径）
  - 是否有未验证的外部依赖
  - 是否有潜在的边界条件问题

### 3. 代码扫描
对「测试结果」为 ⚪未测试 的功能：
- 读取该功能涉及的所有核心源文件
- 识别关键路径和边界条件
- 生成具体的测试建议（含可执行命令或代码片段）

### 4. 输出报告
按优先级排序输出审计报告：

```markdown
## 审计报告 — YYYY-MM-DD (UTC+8)

### 🔴 高优先级
- [FXX] 问题描述 → 建议：解决方案

### 🟡 中优先级
- [FXX] 问题描述 → 建议：解决方案

### ⚪ 待测试
- [FXX] 功能名 — 未验证的关键路径
  - 建议测试命令：`...`
```

### 5. 更新文档
- 将新发现的问题写入对应 `features/fXX-*.md` 的「已知问题」表
- 将测试建议写入对应 feature 文件的「测试方法」字段
- 更新 `index.md` 的状态列（如状态发生变化）

### 6. 提交
```bash
git commit -m "docs(audit): 审计报告及文档更新"
```

## 注意事项
- 审计基于当前代码和文档状态，不猜测
- 优先级标准：
  - P0（🔴）：数据丢失、服务不可用
  - P1（🔴）：核心功能受损
  - P2（🟡）：非核心问题、代码质量
  - P3（⚪）：改善建议
- 每次审计都应产出可执行的改进建议
