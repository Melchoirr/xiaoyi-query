# catch-up

## 流程

1. **扫描** — `git log --format="%ai %H %s" -20` 获取提交历史。遍历源码目录读关键文件。读现有 features/（如有）对比代码。

2. **划分功能** — 按逻辑功能划分，非按文件。一个功能 = 协同完成同一职责的代码（可跨多文件）。粒度：会被独立修改、独立测试的最小逻辑单元。避免过细（每文件一功能）或过粗（整模块一功能）。

3. **生成 features/fXX-*.md** — 每个功能一个文件：

   ```markdown
   # [FXX] 功能名称

   ## 状态
   - **实现状态**：✅已完成 / 🔧进行中 / 📋计划中 / ❌已废弃
   - **核心文件**：
     - `path/file.py:行号` — 类/函数，职责
   - **功能描述**：从源码提取，不猜测。
   - **测试方法**：可执行命令或代码片段。

   ## 变化

   ### [实现] YYYY-MM-DD HH:MM — 初始实现 (`hash`)
   <details><summary>详情</summary>

   **计划**：功能目标
   **代码修改**：新增了什么
   **测试**：
   | 方法 | 结果 | 备注 |
   |------|------|------|

   </details>
   ```

4. **生成/更新 index.md** — 架构概览 + 功能清单表 + 全局问题汇总（从 features/ 聚合，加链接）。

   | ID | 功能 | 核心文件 | 最初实现 | 最后变更 | 状态 | 维护 | 详情 |
   |----|------|----------|----------|----------|------|------|------|

5. **Commit** — `git add record/ && git commit -m "docs(catch-up): 同步文档至当前代码状态"`

## 约定
- 时间：UTC+8，`YYYY-MM-DD HH:MM`。用 `git log --format="%ai"` 获取精确时间。
- ID：FXX 递增，读 index.md 最大 ID 后 +1。
- 不猜测实现细节，直接读源码。
