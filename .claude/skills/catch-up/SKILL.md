# 文档追赶流程

## 触发场景
- 项目首次建立文档体系
- 发现文档与代码不同步（其他开发者修改了代码但没更新文档）
- 长时间未维护文档后恢复

## 执行步骤

### 1. 扫描现状
- 运行 `git log --format="%ai %H %s" -20` 获取近期提交（含精确时间）
- 如有已提交的历史：`git diff HEAD~N --stat` 查看变更范围
- 遍历项目源码目录，读取关键代码文件
- 读取现有 `record/project/features/` 文件（如有），对比代码实际情况

### 2. 划分功能边界

按**逻辑功能**划分，而非按文件划分。划分原则：
- 一个功能 = 一组协同完成同一职责的代码，可以跨多个文件
- 一个文件也可以属于多个功能（如一个文件中包含多个独立职责）
- 粒度标准：**会被独立修改、独立测试、独立讨论**的最小逻辑单元
- 避免过细（每个文件一个功能）或过粗（整个项目一个功能）

示例：
- ✅ "预测模型层"（包含 3 个模型文件 + embedding 层）= 1 个功能
- ✅ "数据管道"（数据加载 + 工厂 + 时间编码）= 1 个功能
- ❌ "DLinear.py" = 1 个功能（太细，除非它有独立的迭代生命周期）
- ❌ "整个 forecast/" = 1 个功能（太粗）

### 3. 识别差异
对每个功能：
- 代码有变更但 feature 文件未更新 → 需要 catch-up
- 新增了代码但无对应 feature 文件 → 需要新建
- feature 文件描述的功能已被删除 → 标记为弃用
- 已有 feature 文件内容与代码一致 → 跳过

### 4. 生成/更新功能详情文件

对每个需要处理的功能，读取源代码后按以下模板生成 `record/project/features/fXX-kebab-name.md`：

```markdown
# [FXX] 功能名称

> 最后更新：YYYY-MM-DD HH:MM (UTC+8)

## 概述
功能用途和在架构中的位置。（读源码后填写，不要猜测）

## 实现
- **状态**：✅已完成 / 🔧进行中 / 📋计划中 / ❌已废弃
- **核心文件**：
  - `path/file.py:行号` — 类名/函数名，职责描述
  - （一个功能可以包含多个文件，全部列出）
- **实现方式**：技术要点，关键算法，输入输出规格。（从源码中提取）
- **设计决策**：引用 ADR-XXX（如适用）

## 测试
### 测试方法
可执行的测试命令或代码片段。（根据功能特性设计）

### 测试结果
| 日期 (UTC+8) | 方法 | 结果 | 备注 |
|--------------|------|------|------|
| （暂无记录） | | | |

## 问题跟踪
### 已知问题
| 问题 | 优先级 | 发现日期 | 状态 |
|------|--------|----------|------|

### 解决记录
| 问题 | 解决方案 | 解决日期 | 验证 |
|------|----------|----------|------|

## 时间线
| 时间 (UTC+8) | 事件 | commit |
|--------------|------|--------|
```

### 5. 生成/更新索引文件

更新 `record/project/index.md`，包含：

- 架构概览（一段简要描述 + 层次图）
- 功能清单表：

| ID | 功能 | 核心文件 | 最初实现 | 最后变更 | 状态 | 维护 | 详情 |
|----|------|----------|----------|----------|------|------|------|

核心文件列：列出功能涉及的主要文件/目录（多个用逗号分隔）。

状态图例：
- ✅无误 / ⚠️有注意事项 / 🔴有Bug
- 🟢在用 / 🟡冻结 / 🔴弃用

- 全局问题汇总表（从各功能节点的已知问题中聚合）

### 6. 生成/更新设计决策

如发现代码中体现了重要的设计选择（技术选型、架构模式等），追加到 `record/project/decisions.md`。

ADR 格式：
```markdown
## ADR-XXX — 决策标题

- **日期**：YYYY-MM-DD
- **状态**：提议 / 已采纳 / 已废弃
- **背景**：为什么需要做这个决策
- **决策**：选择了什么方案
- **理由**：为什么选这个方案（含备选方案对比）
- **代价**：这个方案的缺点
- **影响**：对代码结构的影响
```

### 7. 提交
```bash
git add record/
git commit -m "docs(catch-up): 同步文档至当前代码状态"
```

## 注意事项
- 所有时间戳使用北京时间 (UTC+8)
- 使用 `git log --format="%ai %s"` 获取精确 commit 时间
- 不要猜测实现细节，直接读源码
- 功能 ID（FXX）递增分配，文件名用 kebab-case
- index.md 日期列简写为 MM-DD HH:MM
