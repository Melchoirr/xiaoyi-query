# 文档更新流程

## Plan 阶段（产出 plan 时）

当你为某个功能创建实施计划时：
1. 读取 `record/project/index.md`，根据功能清单表定位涉及的功能 ID
2. 读取对应 `record/project/features/fXX-*.md`
3. 在「时间线」追加：`📋 计划: [计划描述]`
4. 如果是新功能，新建 `features/fXX-name.md`，实现状态设为 📋计划中
5. 更新 `index.md` 对应行（状态列）

## Execute 阶段（代码修改后）

代码修改完成后：
1. 运行 `git diff --stat` 查看本次变更的文件
2. 读取 `record/project/index.md` 的功能清单表，根据核心文件列匹配变更文件，识别涉及的功能（一个文件可能关联多个功能，一个功能可能涉及多个文件）
3. 读取对应 `features/fXX-*.md`
4. 更新以下字段：
   - **实现状态**：📋计划中 → 🔧进行中 / ✅已完成
   - **核心文件**：如有新增文件，补充到列表
   - **实现方式**：根据 diff 更新技术描述
   - **时间线**：追加变更记录（含 commit hash）
5. 如果运行了测试，更新「测试结果」表
6. 更新 `index.md`（最后变更、状态列）
7. 如有新的设计决策，追加 `decisions.md`

## 更新决策矩阵

| 你做了什么 | 更新什么 |
|------------|----------|
| Plan 了某功能 | 功能详情 时间线 + 索引 状态列 |
| 实现了新功能 | 新建 feature 文件 + 索引新增行 |
| 修改已有功能 | 功能详情（实现方式+时间线） + 索引（最后变更） |
| 发现 Bug | 功能详情 问题跟踪 + 索引 状态列 |
| 修复 Bug | 功能详情 解决记录 + 索引 状态列恢复 |
| 运行测试 | 功能详情 测试结果表 |
| 做设计决策 | decisions.md 新增 ADR |
| 删除/弃用功能 | 索引 维护列改为 🔴弃用 |

## 如何定位变更文件对应的功能

**不依赖硬编码映射表**，而是每次通过 index.md 的「核心文件」列动态匹配：
1. 读取 index.md 功能清单表
2. 对每个变更文件，在核心文件列中查找包含该文件（或其所在目录）的功能行
3. 如果没有匹配到任何功能：
   - 判断是否属于某个现有功能的自然扩展（如同目录下的新文件）→ 更新该功能的核心文件列表
   - 判断是否构成一个全新功能 → 新建 feature 文件 + 更新 index.md
   - 判断是否是辅助文件（配置、CI等）→ 不需要对应功能

## 格式规范
- 时间戳：`YYYY-MM-DD HH:MM` (UTC+8)
- 功能 ID：FXX 递增（读取 index.md 当前最大 ID 后 +1）
- 文件名：`fXX-kebab-case.md`
- index.md 日期列简写：`MM-DD HH:MM`
- commit 消息：`docs: 更新 FXX 功能文档`
